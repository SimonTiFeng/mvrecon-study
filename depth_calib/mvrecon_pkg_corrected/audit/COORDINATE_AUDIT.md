# MV-Recon coordinate/scoring audit (2026-11-23)

## Findings

The user correctly identified a scorer bug. A second, independent bug was found in the COLMAP pose conversion.

### 1. COLMAP pose convention was reversed

COLMAP `images.txt` stores **world-to-camera** extrinsics:

```
p_cam = R_wc p_world + t_wc
```

The correct transform from view j's camera coordinates into reference view i's camera coordinates is:

```
R_ij = R_i R_j^T
t_ij = t_i - R_i R_j^T t_j
```

The original `make_gt.py` instead used `R_i^T R_j` and `R_i^T(t_j-t_i)`, treating the poses as camera-to-world. `make_gt.py` and the task matrices were regenerated with the correct formula. The independent verification in `bench/test_transform_convention.py` checks both a random 3D point and a real office view pair; max formula error is zero on all 61 current task transforms.

### 2. Cumulative M was scored against incremental A

For each target cloud:

- Initial cumulative transform: `M0 = D_injected`.
- The correct incremental recovery is `A = T_true @ inv(D_injected)`.
- Operations are left-composed, so `M_final = A @ M0 = T_true`.

The old scorer compared `M_final` to `A`, rather than to `T_true`. The corrected scorer strips uniform scale from the estimated matrix, compares rotation to `T_true[:3,:3]`, and compares translation to `T_true[:3,3]`. It also records scale error.

`workbench/wb.py::apply` was corrected at the same time. An incremental similarity `Q=(s_i,R_i,t_i)` now composes as `M_new=Q@M_old`, including rotating/scaling the previous translation correctly.

### 3. Exact reproduction of the user's office-v2 discrepancy

In the **archived pre-fix handoff** (`archive/pre_pose_fix/`), office v2 is `eth3d_0130` (ref) / `eth3d_0135` (target):

| quantity | rotation error |
|---|---:|
| saved legacy JSON | 83.4 deg |
| archived D vs legacy scorer's incremental A | 56.112 deg |
| archived D vs archived (wrong-convention) T | 18.559 deg |
| archived D vs correctly recomputed COLMAP T | 31.302 deg |

Thus the user's 56.1-degree calculation is reproducible as `D` vs the legacy incremental `A`; the saved 83.4-degree result does not reproduce from the archived task under either formula. This is an additional **task/result version mismatch**: the scalar result file was not generated from the task matrix in the handoff.

The current corrected task has a different office-v2 pair (`eth3d_0127` / `eth3d_0133`); its identity score is 66.058 degrees and the stored baseline row matches it exactly. The current task's subset IDs, D matrices, T matrices, result matrices and operation traces all cross-check with zero mismatches.
